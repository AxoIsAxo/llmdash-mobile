# LLMDash Mobile

A native Android (Capacitor) wrapper around the [LLMDash](https://codeberg.org/axoisaxo/LLMDash) React chat frontend. The LLMDash server URL is **baked into the APK at build time** and cannot be changed by the end user at runtime — to ship a build for a different server, fork this repo and rebuild.

The web frontend (chat, models, tools, settings) is identical to the upstream LLMDash SPA. Only the deployment shape differs: instead of a Docker image, you get an Android APK that talks directly to your LLMDash instance.

## Quick start

### Prerequisites

- **Node.js 22+** and **npm**
- **JDK 17 or newer** with `JAVA_HOME` set and `$JAVA_HOME/bin` on `PATH`
- **Android SDK** with `platforms;android-35` and `build-tools;35.0.0` installed
- An **Android device or emulator** for testing

> This branch is mobile-only and does **not** contain the LLMDash backend. Run the backend separately (see the [upstream repo](https://codeberg.org/axoisaxo/LLMDash)) or point the app at an existing instance.

#### Tell the build where the Android SDK is

The Gradle build needs to know where the SDK is. Either **export `ANDROID_HOME`** in your shell, or just let `mobile:setup` auto-detect it (it probes `~/android-sdk`, `~/Android/Sdk`, `/opt/android-sdk`, `/usr/local/android-sdk`, and falls back to `ANDROID_SDK_ROOT`). To silence the auto-detect warning, add the export to your shell rc:

```bash
# ~/.bashrc, ~/.zshrc, etc.
export ANDROID_HOME="$HOME/Android/Sdk"
export PATH="$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH"
```

#### Installing the SDK packages you need

If you have the SDK at `$ANDROID_HOME` but not `platforms;android-35` / `build-tools;35.0.0`, accept the licenses and install them:

```bash
yes | sdkmanager --licenses
sdkmanager "platforms;android-35" "build-tools;35.0.0" "platform-tools"
```

### One-time setup

```bash
cd frontend
npm install
npm run mobile:setup
```

`mobile:setup` will ask for your LLMDash server URL the first time and write it to `frontend/.env` (gitignored). It then scaffolds `frontend/android/` and writes `frontend/android/local.properties` (gitignored) pointing at your Android SDK.

`mobile:setup` is idempotent: if `frontend/android/build.gradle` already exists, it skips `cap add android` so you can never accidentally clobber customizations. To re-scaffold from scratch, delete `frontend/android/` and re-run.

### Build a debug APK

```bash
cd frontend
npm run mobile:build:debug
```

The APK lands at:

```
frontend/android/app/build/outputs/apk/debug/app-debug.apk
```

Install it on a connected device with:

```bash
adb install -r frontend/android/app/build/outputs/apk/debug/app-debug.apk
```

### Build for a different server

The prebuild script reads `LLMDASH_SERVER_URL` from the first source that has it, in this order:

1. **Environment variable** — `LLMDASH_SERVER_URL=https://...` (good for CI)
2. **Repo-root `.env`** — `LLMDASH_SERVER_URL=https://...` in a `.env` file at the repo root
3. **`frontend/.env`** — auto-generated by the previous build; you only need to set the URL once per checkout
4. **Interactive prompt** — only if `stdin` is a TTY
5. **Fail-fast** — if none of the above and not a TTY, the build exits 1 with instructions

To target a different server, any of these work:

```bash
# Override for one build
LLMDASH_SERVER_URL=https://llmdash.example.com/ npm run mobile:build:debug

# Set it once in the repo root
echo "LLMDASH_SERVER_URL=https://llmdash.example.com/" > ../.env
npm run mobile:build:debug

# Or just delete frontend/.env to be re-prompted
rm frontend/.env
npm run mobile:build:debug
```

### Local development against a running backend

Point `LLMDASH_SERVER_URL` at `http://10.0.2.2:8000/` (Android emulator's view of the host machine) while you have the LLMDash backend running locally.

## Build via CI

A GitHub Actions workflow at `.github/workflows/build-mobile.yml` builds the debug APK on demand:

1. Push this repo (or a fork) to GitHub
2. Go to **Actions → Build Mobile APK → Run workflow**
3. Enter your LLMDash server URL
4. Download the `llmdash-debug-apk` artifact from the completed run

## Customizing the app

### App icon and splash

Drop a `frontend/resources/icon.png` (1024×1024) and `frontend/resources/splash.png` (2732×2732), then:

```bash
cd frontend
npm run mobile:icons
```

This regenerates all density-specific launcher icons and splash drawables via `@capacitor/assets`.

### App name and package id

Edit `frontend/capacitor.config.ts` (`appId`, `appName`) and `frontend/android/app/src/main/res/values/strings.xml` (`app_name`, `title_activity_main`). Note that `appId` is the Android package name and is immutable on Play Store uploads.

### Theme colors

- System bars / splash background: `frontend/capacitor.config.ts` → `backgroundColor`
- Web app theme: `frontend/index.html` → `<meta name="theme-color">`
- Brand colors inside the app: `frontend/src/index.css` and the CSS variables in `frontend/src/css-preset.ts`

## How it works

1. **`prebuild.mjs`** reads the server URL from `LLMDASH_SERVER_URL` (env), `../.env` (repo root), or an interactive prompt. It writes `frontend/.env` with `VITE_API_BASE=<url>/api`.
2. **Vite** builds the SPA into `frontend/dist/`.
3. **`cap sync android`** copies `dist/` into `frontend/android/app/src/main/assets/public/`, writes `capacitor.config.json` + `capacitor.plugins.json`, and updates plugin references.
4. **`./gradlew assembleDebug`** compiles the APK with the bundled web assets and native plugins.
5. The APK is self-contained: launching it opens the Capacitor WebView, which loads the bundled SPA, which calls `https://your-server/api/*` directly (cross-origin, allowed by the backend's `allow_origins=["*"]` CORS).

### Storage

JWT auth tokens are stored in `@capacitor/preferences` on Android (encrypted shared prefs) and fall back to `localStorage` in a regular browser. See `frontend/src/storage.ts`.

### Native plugins enabled

| Plugin | Purpose |
|---|---|
| `@capacitor/preferences` | Secure token storage |
| `@capacitor/status-bar` | Match the dark theme on the system status bar |
| `@capacitor/splash-screen` | Branded launch screen |
| `@capacitor/app` | Back-button handling, lifecycle events |
| `@capacitor/network` | Detect online/offline state |
| `@capacitor/keyboard` | Adjust viewport when the keyboard appears |

## Troubleshooting

### `SDK location not found` / `mobile:setup` bails out about `ANDROID_HOME`

Gradle can't find the Android SDK. Either:

```bash
export ANDROID_HOME=/path/to/android-sdk
export PATH="$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH"
```

…or create `frontend/android/local.properties` (gitignored) with:

```
sdk.dir=/path/to/android-sdk
```

`mobile:setup` will also auto-detect the SDK at `~/android-sdk`, `~/Android/Sdk`, `/opt/android-sdk`, or `/usr/local/android-sdk` and write `local.properties` for you (it prints a warning suggesting you add the export to your shell rc so future shells find it too).

### `mobile:setup` says "android platform has not been added yet" on the next build

`mobile:setup` exited without scaffolding `frontend/android/` (probably because of the SDK error above). Re-run it once the SDK path is resolved, then `mobile:build:debug` will work.

### Build is missing the dark theme or allows cleartext HTTP

A `cap add android` run from a dirty tree may have overwritten the customizations in `AndroidManifest.xml`, `res/values/colors.xml`, and `res/xml/network_security_config.xml`. The fix is checked in on the `mobile` branch — make sure your local files match. To avoid the problem: re-apply the three customizations *after* any `cap add android` (or just never delete `frontend/android/`).
